# 專案詞彙表維護

本 Skill 只處理專案專屬的業務術語、領域縮寫與跨模組語意。一般程式概念、框架術語與命名慣例不納入 `GLOSSARY.md`。

## 啟動前提

- 先讀取專案根目錄的 `AGENTS.md` 與宣告的詞彙表路徑。
- `AGENTS.md` 未宣告詞彙表時，使用者仍可手動觸發本 Skill 討論術語，但討論結果不寫入 `GLOSSARY.md`。
- 詞彙表路徑不存在時，回報缺件；建立詞彙表檔案需由 `project-setup` 或使用者明確授權。

## 自動介入範圍

本 Skill 可由 Agent 主動載入，介入範圍限於下列情形：

- 該詞已收錄於 `GLOSSARY.md`，且當前對話或程式碼的用法與表中定義不符。
- 同一詞彙在使用者說法與程式碼行為之間出現語意矛盾。

未收錄的新名詞不觸發本 Skill，不對其詢問是否建立詞條。收詞由使用者手動觸發，理由是判斷某個詞是否值得成為專案術語需要業務脈絡，逐詞詢問會使討論被術語登記打斷。

自動載入的權限僅止於提出質疑。寫入 `GLOSSARY.md` 一律依下節規定，取得使用者確認後才執行。

## 維護紀律

- 使用者提出的用詞與現有詞彙表衝突時，當場列出衝突定義、影響範圍與推薦用詞，取得確認前不放行後續文件或程式碼寫入。
- 使用者與程式碼使用的同一詞彙語意矛盾時，當場攤開來源、實際行為與待決差異，交由使用者決定業務語意。
- 術語一旦由使用者確認，立即寫入 `GLOSSARY.md`，不批次累積到結案才寫。
- 每筆內容至少包含術語、定義與使用範圍；同義或禁止用詞放入 `_Avoid_` 清單。
- 保留 `GLOSSARY.md` 既有內容，只追加或針對使用者確認的詞條修改，不重排無關詞條。

## 驗證

- 確認新增詞條屬專案業務語意，而非一般程式概念或命名慣例。
- 確認衝突已由使用者確認，且變更已立即寫入宣告的詞彙表路徑。
