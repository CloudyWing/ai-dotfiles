# 文件編輯規範

## 內容保留

- 重整筆記大綱時只重新排序與分組，保留使用者原始段落。
- 需要精簡時，先列出擬刪除段落並取得使用者確認，再執行刪除。

## 內容驗證與事實查閱

修改技術筆記時，版本號、API 名稱或設定格式可能過時或有誤時，以 `⚠️ 待確認：` 標記，不直接修正。對時效性有疑慮的內容，提示使用者查閱官方文件，不依訓練資料補充最新資訊。

使用者要求驗證時，明確說明查閱依據，例如官方文件、規格文或實驗結果。訓練資料無法確認時，誠實標示不確定性。說法部分正確、部分有誤時，拆開逐條說明。

## 排版校稿

- 檢查標點符號、全形半形混用、中英文間距與段落對齊。
- 中文字與英文字母或數字之間加一個半形空格，例如 `C# 的 IDisposable 介面`。
- 中文語境使用全形標點 `，。：「」`，英文語境使用半形標點，例如 comma、period、colon 與 parentheses。
- 不修改程式碼區塊、反引號內容、引用的原始訊息與使用者刻意保留的格式。

## 文件寫入模式

修改現有文件預設使用 Merge 模式。執行下列步驟：

1. 通讀現有文件全文，理解架構、行文風格與詳細程度。
2. 找出語意對應位置，將新內容插入現有結構。
3. 讓補充內容的深度與精細度符合現有文件。
4. 維持全文語氣與結構一致。
5. 不另建 `*-supplement.md` 或 `*-appendix.md` 填補同一文件缺口。
6. 插入或刪除後重讀受影響區段。大改讀整章，小改讀鄰近段落。

重讀時檢查下列項目：

- 增刪項目後，總數與「分 N 類」「以下三點」等敘述是否同步。
- 編號、名稱與步驟交叉引用是否仍指向正確位置。
- 新增內容是否與其他段落重複。
- 新內容是否與既有敘述矛盾。
- 插入段落與上下文的語氣、邏輯是否連貫。

單點機械修改只需確認該行與鄰近上下文。Append 模式僅用於 log、changelog、進度紀錄，或產出規範明確宣告使用 Append 模式的文件。
