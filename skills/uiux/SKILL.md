# UI/UX 決策規範

本 Skill 依上述觸發語自動載入。自動觸發依賴模型判斷，不保證每次命中，因此當本輪工作涉及畫面而本 Skill 未被載入時，可直接以 `/uiux` 手動強制載入。

本 Skill 規範的是 UI 決策的方法與邊界，不訂定任何具體色碼、間距或字級數值。專案專屬的視覺數值由 `uiux-baseline` skill 掃描產出的樣式基準檔承載。

## 既有慣例優先

專案既有的畫面慣例優先於本 Skill 的預設作法。兩者衝突時以專案既有慣例為準，不主動將既有風格改成本 Skill 的預設。此原則對稱於全域規則 §3.1 對既有 C# 專案的慣例對齊要求。

視覺數值一律引用 `<work-root>/.local/ai-sessions/style-baselines/ui-style-baseline.md`。基準檔不存在時，先執行 `uiux-baseline` skill 產生，不以記憶中的通用數值代替。基準檔的「待決策項」中的值在被採用前須先取得使用者確認。

慣例對齊的層次高於數值對齊。畫面中的查詢條件列、資料表格、彈窗等結構，優先整段複用基準檔「常用模式範例」的骨架，其次才用原子值自行組裝。只對齊色彩與間距而重寫結構，產出的畫面仍會偏離專案既有版型。

## 版面資訊層級決策

動任何畫面前，必須先對區塊做重要性排序，完成歸類後才決定空間配置。

### 三層歸類

| 層級 | 定義 | 配置原則 |
| --- | --- | --- |
| P0 主要動作區 | 使用者進入此畫面的主要目的所在 | 佔據進頁即見的位置與最大視覺權重 |
| P1 次要資訊區 | 支援主要目的、經常被查看但非入頁目的 | 次於 P0，仍維持可見 |
| P2 罕用收折區 | 偶爾使用的設定、進階選項、歷史紀錄 | 預設收合，需要時展開 |

### 判定依據

歸類依下列三項判斷：

- 使用者進入此畫面的主要目的是什麼。
- 各區塊的使用頻率。
- 誤操作的後果嚴重度。後果嚴重的操作不放在最容易誤觸的位置。

### 禁止事項（Crucial）

**禁止依需求清單的條列順序或 `design.md` 的敘述順序鋪排區塊。** 敘述順序反映的是撰寫順序，不是重要性。照著文件順序由上而下疊區塊，結果是每個區塊看起來一樣重要，等於沒有版面。

無法判定某區塊的層級時，列入需確認項交由使用者決定，不預設為 P1。

## 改動邊界與不可自由裁量清單

收到模糊指令（如「優化版面」「調整一下」）時，預設只動下方第一張清單的範圍。

### 可自行決定

- 區塊間距。
- 同層級內的排列順序。
- 收折與展開的預設狀態。
- 次要元件的選用，例如以下拉選單取代單選群組。

### 須先回報並取得確認

- 主色系與品牌識別，含 logo、品牌色、字體家族。
- 既有元件庫的選型與替換。
- 資訊架構的大幅調整，例如頁面拆併、導覽層級變更。
- 既有互動模式的變更，例如將既有的頁內展開改為彈窗。

判斷第二張清單的項目確有問題時，於決策攤開機制中列為需確認項並停止，不先斬後奏。

## UI 決策攤開機制

完成畫面決策後，必須以下列固定格式輸出說明。此格式的作用是讓不具 UI/UX 背景的把關者，以業務重要性判斷版面是否合理。

```markdown
## 版面決策說明

| 區塊 | 層級 | 位置 | 理由 |
| --- | --- | --- | --- |
| ＜區塊名＞ | P0 主要動作區 | ＜位置描述＞ | ＜以業務行為陳述的理由＞ |

**本次未變更**：＜逐項列出刻意維持原樣的項目＞

**需你確認**：

| 項目 | 為何需要你決定 |
| --- | --- |
| ＜項目＞ | ＜落在不可自由裁量清單的哪一條＞ |
```

理由欄必須以業務行為陳述，例如「使用者每日進入本頁的主要目的是處理待簽核項目」。禁止以視覺詞彙陳述，例如「這樣比較平衡」「視覺動線較順」。視覺詞彙無法被非設計背景的把關者驗證，等於沒有給出理由。

「需你確認」無項目時保留標題並填「無」，不整節省略。

## 互動狀態

下列五個狀態為必備。任一畫面規劃或實作都必須交代五態的呈現方式，不得只做正常有資料的情境。

| 狀態 | 要求 |
| --- | --- |
| 載入中 | 明確的載入指示，不留空白畫面 |
| 空資料 | 須含說明文字與下一步動作指引，不得只留空白 |
| 錯誤 | 指出可採取的行動，不只顯示錯誤代碼 |
| 停用 | 視覺上可辨識為不可操作，並說明停用原因 |
| 提交中 | 阻擋重複提交 |

## 響應式版面

採行動優先。先確立窄螢幕的單欄堆疊順序，依 P0、P1、P2 排序，再往上加寬。

- 斷點沿用專案既有定義。基準檔未記錄斷點時，才使用常見三段（約 640、1024、1280），並在決策攤開說明中註明為推定值。
- 表格於窄螢幕降級為卡片式呈現，或改為橫向捲動並固定關鍵欄。
- 觸控目標的最小可點擊區域不小於 44 px 見方，相鄰目標間距不小於 8 px。
