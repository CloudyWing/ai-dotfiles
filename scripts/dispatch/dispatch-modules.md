# Dispatch 模組索引

入口 `scripts/Invoke-CodexDispatch.ps1` 依下列順序以 dot-source 載入模組。函式定義共用入口的 script scope。

| 載入順序 | 模組 | 責任 | 主要函式 |
| ---: | --- | --- | --- |
| 1 | `common-runtime.ps1` | OS 判定、路徑正規化、外部程序與 Git 命令包裝、文字輸出、File.Replace 暫時性錯誤重試 | `Test-IsWindowsPlatform`、`Invoke-FileReplaceWithRetry`、`Resolve-AbsolutePath`、`Test-PathWithinRoot`、`Invoke-ExternalCommand`、`Invoke-GitCommand`、`Write-Utf8NoBom` |
| 2 | `git-baseline.ps1` | Git repository 狀態、carry-in、working tree snapshot、baseline 與輸出路徑守衛；Preflight 起點原始位元組對齊時，以已驗證的目的屬性 handle 清除唯讀狀態、透過 `ReOpenFile` 取得寫入 handle，目的檔為 hard link 時一律拒絕；目的檔原始長度不超過 16 MiB 時，寫入失敗會回復原始位元組與長度；超過 16 MiB 時不預先截斷，失敗可能留下部分覆寫內容或已改為來源長度；並於完成或失敗後還原原屬性；非 Windows 遇到長度不同的覆寫會在寫入前拒絕 | `Apply-SourceCarryIn`、`Initialize-DispatchBoundFileCopy`、`Sync-DispatchTrackedRawBytesFromSource`、`Get-DispatchFileSnapshot`、`New-DispatchBaseline`、`Read-DispatchBaseline`、`Get-DispatchIncrementalChanges`、`Resolve-DispatchBaselineBinding` |
| 3 | `dispatch-scope.ps1` | Request 欄位驗證、派遣單第 3、4、7 欄解析、單位解析、ScopePlan 與 continuation 範圍 | `Read-DispatchOrderSections`、`Apply-DispatchRequest`、`Assert-DispatchRequestRequiredField`、`Assert-DispatchProfileSelected`、`Get-DispatchDeclaredUnitList`、`New-ScopePlan`、`Get-ScopePlanFingerprint`、`Test-ContinuationScopePlan` |
| 3a | `dispatch-input-checks.ps1` | Request 階段輸入檢查與 Finding 彙整 | `New-DispatchInputFinding`、`Invoke-DispatchInputChecks`、`Assert-DispatchInputFindings`、`Get-DispatchOrderLocation`、`Test-DispatchOrderRequiresDesign`、`Test-DispatchRequiredIdentifierResolvable` |
| 4 | `dispatch-evidence.ps1` | Parent options、模型證據、Profile 診斷、檔位名稱與帳號檔位連結檢查、登記帳號的登入判定（只讀檔案 metadata）與候選清單、帳號選擇（`explicit`、`unregistered`、`auto`）、候選階段的專案信任唯讀預檢（`config.toml` 不存在、為連結或格式不支援的帳號列入略過清單）、選定帳號後以 `Confirm-CodexAccountProjectTrust` 在鎖內補上專案信任（信任鍵為 `SourceRoot` 的 git 主工作樹根）、evidence binding | `New-ParentOptionsModel`、`New-DispatchEvidenceBinding`、`Resolve-CodexHomeForEvidence`、`Read-ProfileModelEvidence`、`Invoke-ModelEnvironmentDiagnostic`、`Get-CodexDispatchProfileNames`、`Get-CodexAccountProfileLinkStatus`、`Test-CodexLegacyDefaultProfile`、`Test-CodexAccountLoggedIn`、`Get-CodexDispatchAccountCandidates`、`Resolve-CodexAccountSelection`、`Resolve-CodexProjectTrustKey`、`Confirm-CodexAccountProjectTrust` |
| 5 | `quota-observation.ps1` | Advisor 授權、CodexHome 解析、optional property 存取與中斷安全點訊息判讀 | `Get-AdvisorActivationDecision`、`Resolve-CodexHomePath`、`Get-OptionalObjectProperty`、`Get-LatestSafePointMessage`、`Test-SafePointMessage` |
| 6 | `advisor-evidence.ps1` | Advisor 契約、Prompt、evidence pack、thread relay 與報告 | `New-DispatchPrompt`、`Assert-AdvisorContract`、`Test-AdvisorEvidencePack`、`Wait-ForThreadRelay`、`Write-AdvisorConsultReport` |
| 7 | `process-identity.ps1` | RunRecord process identity、Windows 與 Unix process snapshot、PID 與 process tree 驗證 | `Read-LineManifest`、`Get-WindowsProcessSnapshots`、`Get-UnixProcessSnapshot`、`Test-RecordedProcessIdentity`、`Get-DescendantProcessIds`、`Get-PidCheckResult` |
| 8 | `reviewer-contract.ps1` | Reviewer 報告與 finding schema 驗證、evidence 連結、finding ledger 與 Collect 判定 | `Test-ReviewerFindingReport`、`Resolve-ReviewerEvidencePath`、`Write-ReviewerFindingLedger`、`Get-ReviewerFindingsForCollect` |
| 9 | `run-recovery.ps1` | RunRecord 與 event stream 讀取、服務端拒絕分類（`usage-limit`、`unauthorized`、`model-not-supported`）與換帳號資格判定、失敗分類（含帳號設定與專案信任的拒絕碼，這些碼不屬服務端拒絕，不換帳號）、續行鏈結與 Collect identity 解析 | `Get-DispatchEventEvidence`、`Test-DispatchAccountFailoverEligible`、`Convert-EventEvidenceToServiceRejection`、`Get-DispatchFailureReasonCode`、`Get-RecoveryChainModel`、`Read-DispatchRunRecord`、`Resolve-PreviousDispatchRun`、`Resolve-InspectDispatchRun`、`Resolve-DispatchCollectIdentityRequestSource`、`Test-DispatchCollectIdentity` |
| 10 | `prepare-stage.ps1` | Prepare root 與目的地解析、stage binding、result 與 failure receipt 讀寫、Prepare 執行 | `Resolve-PrepareDestinationRoot`、`New-DispatchStageBinding`、`Assert-DispatchStageBinding`、`Write-DispatchFailureReceipt`、`Resolve-PrepareResultBinding`、`Invoke-Prepare` |
| 11 | `dispatch-lifecycle.ps1` | Preflight 與 Dispatch 階段協調、worktree resource Dispatch 的第 7 欄 report path 邊界、stage 結果及 Dispatch result binding 寫入、換帳號外層（未指定 `-CodexHome` 的 Dispatch 在服務端拒絕且無 item 進度時依登記順序改試下一個帳號，同一帳號不重送，並寫摘要檔）、選定帳號後 Preflight 前呼叫 `Confirm-CodexAccountProjectTrust` 並把結果與略過原因寫入結果文件的 `project_trust` | `Invoke-Preflight`、`Write-DispatchStageResult`、`Write-DispatchInspectResultBinding`、`New-DispatchResultEnvelope`、`Invoke-Dispatch`、`Invoke-DispatchWithAccountFailover`、`Test-DispatchAccountFailoverApplicable`、`New-DispatchAttemptRequest`、`Invoke-DispatchAttemptProcess`、`Write-DispatchAccountFailoverSummary`、`Invoke-DispatchAccountFailover` |
| 12 | `start-lifecycle.ps1` | Codex launcher 與 executable 選擇、Start evidence、process tree 管理及 Start 執行 | `Get-CodexExecutablePath`、`New-CodexLauncher`、`Write-StartPidRecord`、`Stop-VerifiedProcessTree`、`Initialize-DispatchOutputFile`、`Invoke-Start` |
| 13 | `inspect-lifecycle.ps1` | event 與 exit sidecar 判讀、Dispatch inspect binding 驗證及 Inspect 執行 | `Read-DispatchExitSidecar`、`Wait-DispatchExitAndTerminalEvent`、`Resolve-DispatchInspectBinding`、`Invoke-Inspect` |
| 14 | `collect-contract.ps1` | Requirement summary 與報告解析、需求參照及直接寫入證據驗證、Collect 執行 | `Get-RequirementIdsFromSummary`、`Get-RequirementMap`、`Get-ReportReferencedPaths`、`Get-DirectWriteFileEvidence`、`Invoke-DirectWriteCollect`、`Invoke-Collect` |
| 15 | `cleanup.ps1` | Cleanup identity 驗證、檔案清單與位元組長度及 SHA-256 保存驗證、保留證據及 Cleanup 執行 | `New-CleanupOperationResult`、`Get-CleanupInventory`、`Preserve-CleanupFile`、`Invoke-Cleanup` |
| 16 | `Invoke-DispatchConcurrency.ps1` | Caller Session fingerprint、持久 admission ledger、跨程序獨占鎖、名額與來源路徑互斥、owner 驗證及 Collect source integration | `Get-DispatchCallerSessionIdentity`、`Open-DispatchAdmissionLock`、`Assert-DispatchAdmission`、`Invoke-DispatchAdmissionStart`、`Assert-DispatchAdmissionOwner`、`Invoke-DispatchSourceIntegration` |

`codex-account-config.ps1` 不在上表的載入順序內。它是帳號 `config.toml` 的共用程式庫，沒有 `param` 區塊與主程式區段，由 `Confirm-CodexAccountProjectTrust` 與 `Get-CodexDispatchAccountCandidates` 於函式內以 `$PSScriptRoot` 載入，`scripts/New-CodexDispatchAccount.ps1` 以同一路徑載入，兩處共用單一份實作（`Get-AccountConfigPlan`、`Set-AccountAtomicFile`、`Open-CodexAccountLock`、`Test-AccountTrustReadiness` 等）。複製模組到變體目錄的測試須一併複製此檔。
