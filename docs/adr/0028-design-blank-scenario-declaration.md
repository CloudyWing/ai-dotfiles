# ADR-0028：設計文件對空白情境明文表態，缺少決策不得進入 Developer

## Context

設計文件對需求未描述的情境留白時，Implement 會自行加入未授權的補償行為，例如以缺失資料推導補償資料，問題在正式環境才出現。

## Decision

`Architect` 的設計文件對每個程式面項目或垂直功能路徑，建立涵蓋無資料、資料異常、外部呼叫失敗與併發衝突四種情境的空白情境表，逐列填入具體處置，刻意排除者須在「刻意排除的範圍」列出理由。任一列缺少決策時設計不通過，`Developer` 不得進入實作。攔截點放在 Design 階段，排除以 Review 端的審查補強取代。

## Consequences

設計文件的篇幅增加，Design 驗收須逐列核對。舊設計文件不回填，缺口由後續新設計要求明列。
